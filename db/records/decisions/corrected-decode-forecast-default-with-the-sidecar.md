Carlos asked on 2026-09-16 to ship the corrected forecast, test it, benchmark it and update the docs, after the readout timing confirmation measured it directly against the configuration that shipped.

**Decision.** Wherever the decode lookahead runs ([[records/decisions/decode-lookahead-default-with-the-draft-head]]), its forecast tap is `attention-corrected` when the checkpoint's correction file is present next to the weights, and the boundary stride-2 forecast otherwise. The configuration is exactly the one the confirmations measured: tap attention-corrected with the rank-128 correction `lookahead/tap-correction-attention-rank128-v1.safetensors` (37,540,708 bytes, SHA-256 `37b00d3a32d1e1889a1794bbb8e97905a157a77c0508db620c1a11f2a895f7f5`), margin threshold 0.062, top 24 per target, issue cap 32, 32 staging records, 16 read lanes, slot adoption with at most 64 reserved slots, GPU forecasts, FP32 routers and the four-layer barrier. Nothing else changes. `RouterTapCorrection.shipped` qualifies the file only when its header serves the corrected attention tap and its whole-file digest equals the measured one; a wrong file leaves the boundary forecast in place and the startup banner says why.

**Evidence.** Against the qualified configuration that shipped, on eight held-out prompts from families no earlier run had used, the corrected tap decoded at 1.111 (bootstrap 1.102 to 1.123), all 23 counted pairs above 1, every kind at 1.079 or above, every kind's request duration shorter and every output identical, medians 13.10 to 14.83 tok/s at a 20 GB target ([[records/measurements/decode-forecast-taps-readout-timing-confirmation-2026-09-15]]). The chain behind it: the attention tap at 1.058 over the shipped configuration on B1 (every effect condition passed, the pairs condition failed on swap noise; [[records/measurements/decode-forecast-taps-b1-cohort-2026-09-15]]) and the correction at 1.031 over the plain tap on its own held-out confirmation ([[records/measurements/decode-forecast-taps-learned-confirmation-2026-09-15]]). The direct number supersedes their product. The readout tap, the most accurate forecast measured offline, lost 5% to the corrected tap natively and 26% in its after-demand placement ([[records/measurements/decode-forecast-taps-readout-timing-screen-2026-09-15]]); the lower issue threshold and the co-routing prior failed their gates. The shipping build's own default-path benchmark is [[records/measurements/corrected-forecast-release-benchmark-2026-09-16]].

**Where the file lives.** A pinned optional sidecar of the model mirror, outside the Slotpack objects: `pull` fetches `lookahead/tap-correction-attention-rank128-v1.safetensors` after the weights from the mirror commit `8c1f9c34e4567e83d46cebe1af432e8eba4f3ea8`, verifies size and digest, writes it atomically, and reports and continues on any failure, because a model directory without it runs the previous forecast. `pull --verify` reports its status. A Slotpack row was considered and rejected: the embedded manifest must equal the pinned file table, so a new optional object needs a new manifest revision and a full public pull qualification for a 37.5 MB derived file. The file is derived data for one checkpoint; a new checkpoint needs a new capture and fit, and the header names the tap and the capture it came from.

**Memory.** The plan charges 409 MiB with the file (the 128 MiB staging reserve, 245 MiB of FP32 router copies and the file's 36 MiB, rounded up to whole MiB) and 373 MiB without it. The automatic ceiling does not rise; the bytes come out of the expert pool. `doctor` and the startup banner print the decision and the charge, and the banner names the forecast in use with the reason.

**Overrides.** `SLOTSTREAM_EXPERT_PREFETCH_TAP=boundary` keeps the previous forecast with the file present and charges 373 MiB; it is the arm the release benchmark compared against. `SLOTSTREAM_OPT_EXPERT_PREFETCH=0` turns the lookahead off and charges nothing. The experimental configuration selected by `SLOTSTREAM_OPT_EXPERT_PREFETCH=1` or an explicit reserve is unchanged and may name any tap and correction file.

**Scope.** Timed on one 48 GB M5 Pro with two drafts at a 20 GB target (the confirmations) and at a 22 GB target (the shipping build's benchmark, the smallest target at which the automatic default engages under the benchmark environment). No multilingual prompt in the held-out sets; the correction was trained on the pilot's 56 training requests. Other chips, SSDs and cache sizes are not timed; the public tier estimates were not re-anchored.
