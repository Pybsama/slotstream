# Qualify complete native workflows

A capable model and a passing protocol suite do not establish a usable product. The October capability audit found correct content behind broken file references, an undeclared tool after a valid staged edit, unusable citation links and fenced machine-readable output. A correct current CLI also coexisted with an obsolete app bundle. Preserve the distinction between model quality, tool delivery, evidence presentation, reviewed effects and the executable actually delivered.

## Engineering policy

- Reproduce the person's complete job with synthetic but representative inputs, the production runtime and renderer, and a real maintained model. Keep the original prompts, source bytes, failures and checks before changing code. Add deterministic boundary tests as well as the real-model replay.
- Repair a class of failures at its boundary. Use schema-derived, bounded correction for malformed tool responses instead of executable aliases or an ever-growing list of special spellings. Validate the entire response before its first effect; permission and exact-content review survive recovery.
- Use deterministic host tools for exact arithmetic and bounded data operations. A fluent answer or a small mentally summed example does not qualify general analysis. Report complete versus partial coverage, unsupported formats and precision limits.
- Give attached files directly usable references. Use the same citation grammar for artifact validation and presentation, and resolve only owner-issued evidence. Valid structured syntax is separate from factual or schema correctness. Preserve data bytes when removing presentation-only wrappers.
- Retrieve older permitted evidence on demand instead of silently raising memory budgets. Keep literal retrieval's limitations visible. Forget, scope, Incognito, pagination, cancellation and source identities belong in the tests.
- Qualify the delivered native bundle, including embedded engine and helper identity. Dependency layout changes must rebuild native consumers. Preserve stale-artifact failures as build evidence; do not misdiagnose them as memory shortage or hardware defects.
- Publish a task-by-task capability map. Missing web browsing, audio transcription, sandboxed execution or general image understanding are feature gaps. A prompt saying they are unavailable is an honesty improvement, not their implementation.

## Scope and reversal

This decision does not impose a permanent fixed tool set, one model, or these fixture tasks as a universal benchmark. New capabilities and models should use the same complete-job discipline. Revise operating ceilings or recovery policies when broader representative evidence shows a better reliable tradeoff. Keep held-out tasks and real external use separate from development fixtures.
